# GIF 首帧预览契约

每个动画注册项都有同一 GIF 实际解码出的首帧 PNG；不是原图库静图，也不是重新绘制的近似图。`posterFor(input)` 和 `pathFor(input)` 共享场景、阵营、手动覆盖校验；PNG 路径为 GIF 去掉 `.gif` 后加 `-first-frame.png`。

## 同一套手机 / 电脑行为

1. 到达场景时，仅请求当前场景的首帧和 GIF，不请求其他页/未选分支。首帧优先级高，GIF 低，独立并行。
2. 两端立即把来源设为首帧，GIF 实际加载成功才切换；不为展示首帧故意延迟已就绪 GIF。
3. GIF 失败保留同一首帧，显示失败和手动重试提示，不切回旧图库图片。
4. 首帧本身失败但 GIF 成功时照常显示 GIF；两者都失败明确提示，不伪称已经显示首帧。
5. 手动重试时保留已加载首帧，只重试当前 GIF；若首帧也失败才重试二者。旧回调不能覆盖新场景。
6. “减少动态”直接显示同一首帧，不请求 GIF。用户明确选其他图库背景时仍尊重该覆盖。

代码可处理未来 10 张或更多动画，无需修改引擎，只需加入映射与真实首帧文件。当前三张已有 GIF 的像素一致证据见 `GIF-FIRST-FRAME-EVIDENCE.json`，这是当时映射的证据，不代替未来新增文件核验。

```sh
python scripts/check-gif-posters.py          # 逐像素核验所有当前映射
python scripts/check-gif-posters.py --write  # 从所有最终 GIF 提取首帧，再核验（需要 Pillow）
```

本地专项测试涵盖首帧/GIF 完成先后、分别失败、双失败、旧回调、显式重试、切换场景和减少动态；真实 Chrome CI 验证请求边界、延迟 GIF 期间可见首帧、失败保留首帧，以及状态提示/键盘操作。以对应提交 CI 结果作为浏览器证据，不将脚本存在等同测试通过。
