# AI 工具接口：常用路径

v2.6.3，2026-10-26。这里描述模型实际收到的工具声明与回执；网页设置里的模型服务地址和密钥表单不在本次改动范围内。

本版新增宿主参数校验与统一效果契约；8 个常用工具及最小调用不变。原生操作覆盖自己的 JSON 兼容媒体通道，包括清空；背景和弹窗分别管理。剧情中的视听效果有明确名称与参数类型，无效的可选效果跳过，正文仍可交付。详见 [程序结构检查](ARCHITECTURE-AUDIT.md)。

## 最少操作

| 目的 | 最小调用 | 结果 |
| --- | --- | --- |
| 不知道有什么图片 | `browse_illustrations({})` | 下一层分类及可继续浏览的 `children[].path` |
| 知道想找什么 | `search_illustrations({query:"后金 骑兵 冲锋"})` | 图片短语、内容和适用说明 |
| 展示独立图片 | `show_illustration({token:"后金·骑军突击"})` | 暂存第一段正文后的弹窗 |
| 更换持续背景 | `set_scene_background({token:"后金·关隘烽火"})` | 暂存背景更换，不创建弹窗 |
| 完成剧情 | `deliver_story({story:{beats:[{text:"营门渐开。"}]}})` | 一次交付有效正文 |

游戏提示词仍要求在剧情结尾给出 3 个具象抉择；上面的交付示例只展示程序接受的最小正文结构，不代表完整的叙事要求。

图片短语中的 `·`、`・`、`•` 与空白分隔统一解析；例如 `后金 盛京宫庭` 与 `后金·盛京宫庭` 指向同一图片。注册时按同一规则检查冲突，返回值仍使用策展目录中的标准短语。不同文字仍需登记别名或搜索，省略阵营名称不会猜测图片。

清空本轮弹窗草稿用 `show_illustration({clear:true})`；恢复场景默认背景用 `set_scene_background({clear:true})`。清空时不同时传图片引用、位置或说明，冲突请求返回错误且不改变之前的有效状态。两个工具的清除与提交互不影响，都在正文成功交付后生效。

弹窗的 `afterBeat`、`caption` 可以省略；默认在第 1 段正文后出现。0 为正文前，其他非负整数按阅读分页前的整稿段落计数。相同位置后一次有效选图替换前一次。

## 常驻工具与参数

模型只看到 8 个工具。每轮实际提供的工具由成功注册的插件决定，不凭空声明不可用的插件能力。

| 工具 | 常用参数 |
| --- | --- |
| `browse_illustrations` | `path?`、`page?` |
| `search_illustrations` | `query`、`path?`、`page?` |
| `show_illustration` | `token`，可选 `afterBeat`、`caption`；清空时只传 `clear:true` |
| `set_scene_background` | `token`；恢复默认时只传 `clear:true` |
| `read_world` | `{}`，需要补查世界信息时调用 |
| `read_draft` | `{}`，需要读取已有草稿时调用 |
| `write_draft` | `story`、可选 `mode`，默认 replace，长篇可 append |
| `deliver_story` | 通常直接传 `story`；已有草稿时可传 `{}` |

没有“必须先读世界、写草稿、检查草稿再交付”的固定顺序。已知图片可直接选；普通正文可直接交付；长篇确实需要分步写作时，才用草稿工具。`write_draft` 回执包含整稿段数，模型不需要为了安排图片位置额外查询一次检查工具。`read_draft` 仍能查看已写内容并修订。

## 回执

搜索结果只包含可操作的信息，例如：

```json
{"ok":true,"images":[{"token":"后金·骑军突击","title":"骑军突击","description":"穿甲衣的骑军正在突进。","useWhen":["骑军发动突击"],"avoidWhen":["缓慢转进"]}]}
```

每页默认 8 项，有后续结果时才附加 `nextPage`。继续翻页沿用原来的 `query`、`path`，将返回的 `nextPage` 作为 `page`。没有结果时给出换关键词或浏览分类的提示。分类只返回当前层的 `children`，叶类目通过同样的 `images` 字段返回图片。

选图和背景成功回执为 `{"ok":true}`。宿主仍保留完整待选快照，以处理覆盖、清空、取消和统一提交；不会把整份快照逐次重复发给模型。错误保留稳定 `code` 并给出按当前常用接口修正请求的提示。

## 兼容边界

`protocol.tools` 继续保留执行层的旧声明，插件宿主仍可执行旧 `list_illustrations`、`select_illustration`、`inspect_draft`，并接受原来的 ID、筛选和分页参数。新模型通过 `protocol.forModel(host.tools)` 接收简化声明，旧入口和 `id`、`includeLegacy`、`faction`、`category`、`pageSize` 不再占据常用接口。模型可直接在搜索关键词中写画面设定，也可通过 `path` 缩小范围。

原生工具和兼容 JSON 的图片效果统一使用 `show_illustration`、`set_scene_background`；清空语义一致。JSON、旧 ID、进度备份和旧模型工具调用的兼容能力仍由执行层承接。工具历史的调用 ID 与 arguments 原串保持不变，续步只追加消息，不为精简历史重写已有前缀。

## 本轮检查

- 常用工具声明从 10 个收敛为 8 个，常用图片接口参数从 27 个字段收敛为 11 个字段。统计包含可选参数，不包含未露出的兼容字段。
- v2.6.1 以旧主分支 `89b78fa` 为基线，同一正式图库下，UTF-8 工具声明为 5,563 → 4,595 字节；关键词“军”的首个结果页回执为 4,848 → 2,952 字节。v2.6.2 增加封闭的嵌套效果 schema 后，声明为 5,771 字节；这是序列化字节比较，不是模型 Token 或费用的实测。
- 真实 Worker 测试覆盖一次直接交付、一个短语选图、分页搜索、空结果提示、取消、清空冲突、旧入口兼容以及原生/JSON 一致性。v2.6.2 累计 214 项检查通过，包含新增契约与回溯回归；四阵营、剧情数据和静态构建通过。浏览器回归结果以该提交的 GitHub Actions 为准；模型回复均为模拟数据，没有真实模型选图质量或费用结论。
