# 当前场景按需加载 · 2026-11-17

> 历史记录：后续用户已改为“当前 GIF + 该 GIF 的真实首帧”同时按需加载，失败保留首帧而非旧静图。当前契约以 [GIF-FIRST-FRAME-LOADING.md](GIF-FIRST-FRAME-LOADING.md) 为准。

## 用户要求与本轮边界

网页加载费劲，希望分页下载，最多提前加载下一页图片。本轮采用更保守的 **仅当前场景、零预读**：不扫描剧情树，不下载未选分支，也不预下载下一页。画库仍先展示文字，点击预览才取图；剧情图片弹窗仍到对应段落才展示。

## 代码确认的浪费与修正

- 旧舞台使用 `url(GIF), url(WebP)`：浏览器可同时请求当前动画及静图。新舞台只有一个 URL；GIF 加载错误后才换用原静图。所有原图保留。
- 原 HTML 中隐藏的手机 `<img src>` 也可触发下载。现在只在手机布局时赋值；桌面不再给这个隐藏元素图片源。切换布局会重新同步。
- Google Fonts 改为非阻塞样式加载，失败继续使用已有系统字体。不承诺字体服务可达。
- 同资源重复刷新只恢复展示，不新建探测请求；旧场景错误不能覆盖新场景；已失败 GIF 在本会话返回时保持静图回退。

## 真正的首屏瓶颈仍需区分

没有发现一次预加载整个图片库的代码。`skills-data.js` 是约 5.9 MiB 的原始脚本，含完整四阵营剧情；外部字体也曾是渲染阻塞依赖。原始文件大小不等于实际网络传输量或耗时。此次不拆剧情，以免把同步引擎改成异步加载时破坏读档、回溯和分支。

## 后续真实浏览器验收

本地 Chromium 限制未解除，改由仓库已有 GitHub Actions Chrome 执行器运行，不扩大工作流权限，不调用模型 API。提交 `5978dbf8c302cb7a648833ebc11c2e619fc76a21` 的 [浏览器运行](https://github.com/zjj1280637679-ship-it/jiuzhou-chronicles/actions/runs/44100825302) 中，当前场景网络断言、冷 GIF 失败回退、布局切换、图库按需图片、全场景映射与图片解码均通过；请求记录和截图保存在 `scene-media-network` artifact。

下载审查请求记录确认：进入后金、选择铁军分支、返回、选择草原分支时，只请求实际到达的三张 GIF；没有提前下载它们的静图。开启“减少动态”后才请求当前草原静图。桌面没有下载手机首页 palace-night.webp，返回首页场景未再次发起 GIF 网络请求。无页面 JavaScript 异常。

这验证了 Chrome 中的资源请求边界，不是国内网络速度基准、实体 iPhone Safari 验收或全部页面性能保证。截图审查还发现桌面背景保留了既有 1.2 秒过渡，验收脚本已改为等待过渡结束再截图，不能仅凭请求完成判断画面已经切换。CI 缺少中文系统字体且测试屏蔽外网字体，截图汉字缺字不是用户设备字体表现。
