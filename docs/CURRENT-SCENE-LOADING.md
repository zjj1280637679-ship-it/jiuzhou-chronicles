# 当前场景按需加载 · 2026-11-17

## 用户要求与本轮边界

网页加载费劲，希望分页下载，最多提前加载下一页图片。本轮采用更保守的 **仅当前场景、零预读**：不扫描剧情树，不下载未选分支，也不预下载下一页。画库仍先展示文字，点击预览才取图；剧情图片弹窗仍到对应段落才展示。

## 代码确认的浪费与修正

- 旧舞台使用 `url(GIF), url(WebP)`：浏览器可同时请求当前动画及静图。新舞台只有一个 URL；GIF 加载错误后才换用原静图。所有原图保留。
- 原 HTML 中隐藏的手机 `<img src>` 也可触发下载。现在只在手机布局时赋值；桌面不再给这个隐藏元素图片源。切换布局会重新同步。
- Google Fonts 改为非阻塞样式加载，失败继续使用已有系统字体。不承诺字体服务可达。
- 同资源重复刷新只恢复展示，不新建探测请求；旧场景错误不能覆盖新场景；已失败 GIF 在本会话返回时保持静图回退。

## 真正的首屏瓶颈仍需区分

没有发现一次预加载整个图片库的代码。`skills-data.js` 是约 5.9 MiB 的原始脚本，含完整四阵营剧情；外部字体也曾是渲染阻塞依赖。原始文件大小不等于实际网络传输量或耗时。此次不拆剧情，以免把同步引擎改成异步加载时破坏读档、回溯和分支。

## 验证

- 原单元测试 235 项 + 本轮 7 项 = 242 项通过。
- 四阵营游戏测试、内容检查、静态构建通过。
- 独立代理发现并推动修复：同 URL 去重原先会使“渐变覆盖后重读同场景”丢背景；添加回归测试后复核无发布阻断项。
- 修订既有浏览器脚本并新增 `test-scene-media-browser.mjs`，检查首屏、当前 GIF、未选分支、返回、手机/桌面、减少动态与失败回退的真实请求。
- 当前执行环境启动 Chromium 报 `socket() failed: Operation not permitted`，放宽执行权限后仍相同。因此 **浏览器网络、截图与性能提升尚未实测**，不能把单元测试当作网络验收。

可在有 Playwright/Chromium 的环境执行：

```sh
JIUZHOU_BROWSER_EXECUTABLE=/usr/bin/chromium node test-scene-media-browser.mjs
```

默认请求记录和截图输出到 `/tmp/jiuzhou-media-network`，可用 `JIUZHOU_SCENE_SCREENSHOTS` 覆盖目录。该测试不调用收费模型 API。
