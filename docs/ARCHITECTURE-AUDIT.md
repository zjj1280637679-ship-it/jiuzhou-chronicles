# 程序结构与工具契约检查

2026-10-25，v2.6.2。基线为 `c6a16b4`。检查覆盖主引擎、模型循环、Worker 插件、图库、来源适配、恢复与收藏、移动界面及静态发布。采用源码追踪、真实 Worker 的模拟模型测试和局部有界穷举；没有做整个程序的形式化证明，也没有真实模型叙事质量结论。

## 结论与已修复问题

需要优先收拢的是状态变化的规则与交付边界。图片数量已经由数据注册表承担；主要验证复杂性来自同一效果存在多种入口，以及主引擎同时负责请求、解析、状态和显示。

| 优先级 | 基线问题与具体触发 | 本次处理 |
| --- | --- | --- |
| P1 | 原生 `show_illustration({clear:true})` 清空后，`deliver_story` 的 JSON 内若带旧选图，该图仍会进入正文 | 统一媒体计划；原生操作覆盖自己的通道，包括空结果；背景与弹窗互不覆盖 |
| P1 | `read_world({token:"无关字段"})`、`write_draft({story,unknown:true})` 会成功，`additionalProperties:false` 没有在宿主执行 | 宿主按登记 schema 校验参数，失败时不向 Worker 发调用；正文旧格式单独规范化 |
| P1 | 模型循环接受任意插件输出的 `delivery`，没有检查输出属于哪项操作 | 仅注册的交付工具所属 Worker 的 `deliver_story` / 内部 `accept_delivery` 可以交付，且回执必须 `ok:true` |
| P1 | 成功回合把 `apiHistory` 截为最后 200 条，但旧回溯点用历史数组长度定位；长局后会保留未来历史并丢旧前缀 | 移除静默截断，保持回溯引用的追加历史位置稳定；增加跨 200 条的交付、回溯、备份回归 |
| P2 | `stage_effects` 是任意对象数组；显示器、JSON 解析、插画插件各自解释参数 | 新增共用效果契约与纯状态归并；名称、字段、枚举、有限数值、清空冲突和图片引用统一验证 |
| P2 | 三个内置 Worker 都收到整份上下文，虽然副本隔离，但依赖范围不清楚 | 世界插件只拿世界；剧情插件不拿额外上下文；图库插件只拿图库。自定义插件可声明 `contextKeys` |
| P2 | 连续震屏没有取消旧计时器，旧回调可能提早清除后一次效果，或跨场景修改显示 | 震屏计时器与闪光一样由当前效果持有；替换和场景清理都会取消旧回调 |

没有把所有功能都变成 Worker 插件。纯契约和状态归并应当是普通模块；世界读取、草稿、图库查询沿用现有 Worker 隔离。

## 现在的职责边界

| 模块 | 唯一主要职责 | 关键约束 |
| --- | --- | --- |
| `harness/contracts.js` | 校验项目使用的 JSON Schema 子集与工具参数 | 不转换类型、不替参数填默认值、不修改输入；整数必须安全、数值必须有限 |
| `harness/plugin-host.js` | Worker 生命周期、数据投影、注册、调用、交付归属和释放 | 冲突按配置顺序处理；无效参数不执行；普通工具不能靠附带字段提交正文 |
| `harness/runtime.js` | 向模型追加消息、调工具、接收完整交付 | 不改写旧调用 ID 和 arguments 原串；缺交付插件时在发模型请求前失败 |
| `harness/effects.js` | 效果契约、旧命名适配、媒体状态归并和交付合并 | 无 DOM、无请求、无引擎引用；原生、JSON 和旧图片名共用规则 |
| `harness/protocol.js` | 模型接口声明、简短回执和旧剧情数据投影 | 新接口只声明已知字段；旧元数据经过白名单投影，未知键不进入规范化剧情 |
| `app.js` 的显示分发 | 将已验证的效果显示到网页 | 未知或无效的可选效果跳过，有效正文仍可交付 |

`contracts.js` 实现本项目实际使用的 `type`、`properties`、`required`、`additionalProperties`、`enum`、`items`、`minItems`、`minLength`、`minimum`、`maximum`，不是通用 JSON Schema 引擎。内置执行声明的 `story` 只要求对象，再由剧情规范化保留已知正文、选项和效果；它有意接纳旧存量格式，不等于模型接口允许任意扩展。旧自定义插件未提供 `contextKeys` 时继续得到私人上下文副本；新增插件应显式声明需要哪些数据。

## 媒体状态的不变量

每轮暂存媒体状态只有两个独立通道：弹窗列表、背景寄存器，另各有一个“本轮是否被原生工具操作过”的标记。标记使“从未设置”和“明确清空”可区分。

1. 弹窗操作不会改变背景及其标记，背景操作不会改变弹窗及其标记。
2. 同一正文位置最多一张图；后一次有效设置替换前一次；位置排序稳定。
3. 同一有效赋值重复执行得到同一状态；归并不修改输入。
4. 无效操作不进入归并，不改变之前的有效状态。
5. 原生工具只覆盖自己的 JSON 兼容通道；另一通道和视听效果继续保留。
6. 暂存状态归本轮所有；取消或失败不返回可提交剧情。

回归测试使用六种媒体命令，检查所有长度 1–4 的命令序列，共 1,554 条转换，验证独立性、幂等、位置唯一性、确定性及输入不变性。这是有限域检查，不能代表任意插件、任意历史或整套游戏均已被证明。

## 模型接口的直觉性

常用工具仍为 8 个，没有因架构拆分增加模型要选的工具。已知图片仍只传 `token`，找图时只必填 `query`，普通剧情仍可一次 `deliver_story({story})`，草稿工具按需使用。成功选图仍只回 `{"ok":true}`。

模型的剧情、段落和选项对象关闭额外字段；`stage_effects` 声明三种视听效果及各字段类型、枚举，图片继续使用独立工具。执行层另外承接旧图片名、旧 ID、物品与危险刻度效果，并校验它们的参数。未知效果跳过；不会自动变成默认闪光或任意游戏状态写入。

封闭嵌套 schema 后，8 个工具的 UTF-8 序列化声明由上一版 4,595 增至 5,771 字节；必要调用步骤和必填参数没有增加。这是更明确约束的体积代价，不是 Token、价格或真实选图表现的测量。

## 仍需按顺序拆分的部分

| 顺序 | 目前的耦合 | 建议独立模块及验收目标 |
| --- | --- | --- |
| 1 | `app.js` 仍约 4,500 行、100 个方法；回合推进同时做检定、远端调用、失败恢复、队列和存档 | 提取回合协调模块。仅它负责运行、失败、恢复、提交；解析器和显示器不直接切换回合阶段 |
| 2 | `isExtrapolating`、`isEpilogueSequel`、`needsSuturing` 与 `gameState` 的组合合法性由多处分支维持 | 将剧情模式收敛为主线／自由／后日谈，并与回合阶段分开；用明确迁移函数管理，迁移旧存档时保留适配器 |
| 3 | `callDeepSeekLiveAPI` 同时做请求、JSON 修复、正文与选项规范化、历史和效果提交；原生与兼容路径的正文处理仍不完全相同 | 提取纯响应解析模块，输出规范化剧情与诊断；由回合协调模块统一提交。保留现有短正文、Unicode、取消和坏可选字段回归 |
| 4 | 本地读档、备份验证、引擎恢复、回溯分别维护部分字段规则；历史和回溯点会随局数增长 | 建立一个进度版本与历史归档模块。稳定游标引用历史，明确迁移、读取和恢复；容量不足继续报告真实失败，避免静默丢正文 |
| 5 | 收藏、恢复和图库通过 `window.__vnEngine` 与若干 DOM 事件接入；设置逻辑仍在主引擎内 | 提取界面所需的查询／命令门面，集中事件名和数据载荷。界面不直接依赖任意引擎字段，也无需把每个面板变成插件 |

上述是后续改造点，不是已经拆完的模块。不建议一次搬动整个主引擎：每次先固定一个输入、输出和不变量，再迁移调用点，并验证旧存档与真实浏览器接线。

## 内容规模与维度增长

四阵营目前各 364 个预置节点，共 1,456 个。继续完整展开三分叉会按树深度指数增长，属于编写与校验内容的规模问题；分类索引本身不要求预先生成所有场景组合。后续内容应按当前节点与玩家状态解析，角色、环境、事件和图片各自登记，用明确关联筛选组合，避免把每种组合都变成一份剧情、一个工具名或一段分支代码。

图库目前 56 个登记句柄、默认检索 50 幅；增图不增加工具数量。素材和提示词继续按既有精选、分类、搜索与按需加载机制处理，本次不改变美术和剧情设定。
