# 场景动图状态提示

> 历史记录：后续用户已改为“当前 GIF + 该 GIF 的真实首帧”同时按需加载，失败保留首帧而非旧静图。当前契约以 [GIF-FIRST-FRAME-LOADING.md](GIF-FIRST-FRAME-LOADING.md) 为准。

用户要求：GIF 加载失败不能静默，画面角落应有小状态提示。

- 当前 GIF 正在加载：显示“动图加载中…”。不伪造百分比。
- 15 秒尚未完成：显示“动图加载较慢，可继续阅读”，开放手动重试；这不是取消、关机或自动重试预算，不终止原请求。
- GIF 确认失败：显示“动图未能加载，正在载入静图…”；仅当静图加载成功才改为“已显示静图”。静图也失败则明确提示仍可阅读。
- 用户点击重试：只重试当前场景动图；新查询标识绕开之前失败的缓存，不重新加载游戏，不推进剧情，不下载其他分支。
- 重试过程中保留按钮焦点，重复点击/Enter 不发额外请求、不穿透正文。成功显示“动图已恢复”，3 秒后收起；若按钮仍聚焦则待离焦后收起。
- 状态框在画面右上角、导航栏下方，正文上方；`role=status`/`aria-live=polite`，按钮可键盘使用，整个小区域拦截穿透操作。

加载控制器用版本号和当前探针双重校验异步回调，旧场景、旧重试、旧慢速计时都不能覆盖新状态。所有重试均由用户操作，不自动反复下载。已失败 GIF 在返回时仍走静图，提示失败而不伪称正常动图。

本地：11 项媒体控制器测试，合计 246 项单测及四阵营/内容/构建通过。独立审查修复了提示框点击穿透和重试 URL 复用两点。真实浏览器脚本 `test-scene-media-status-browser.mjs` 已接入原有 Chrome CI；需以对应提交工作流结果确认实际 GUI 验收，不能将本地单测替代浏览器实测。
